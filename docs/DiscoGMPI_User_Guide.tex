\chapter*{About this guide}
\addcontentsline{toc}{chapter}{About this guide}

This manual describes the \pkg{} software as implemented in the repository at
the time of writing. It covers the mathematical model, discontinuous Galerkin
(DG) discretization, Maxwell formulations, MPI decomposition, installation,
mesh preparation, public workflows, examples, tests, benchmarks, diagnostics,
and known limitations.

\pkg{} is the distributed-memory development line derived from DiscoG3D. It is
a separate Julia package and repository. Work performed in \pkg{} does not
overwrite the original DiscoG3D source tree.

\paragraph{Scope.}
The principal production path documented here is the source-free,
three-dimensional Maxwell system on affine tetrahedral meshes, with explicit
time integration. The MPI path supports piecewise-constant isotropic material
properties, PEC, PMC, first-order absorbing, and translational periodic
boundaries. It also supports the six-field nonlinear PML of Abarbanel,
Gottlieb, and Hesthaven for dimensionless homogeneous vacuum problems.
Impressed sources remain future work.

\paragraph{Notation.}
Superscripts $-$ and $+$ denote the local and neighboring traces at a face.
The unit normal $\vect n$ points out of the minus element. The polynomial
degree is denoted by $N$, the number of volume nodes per tetrahedron by
$N_p$, and the number of nodes per triangular face by $N_{fp}$.

\chapter{Overview}

\section{Purpose}

\pkg{} provides:

\begin{itemize}[leftmargin=*]
  \item nodal DG operators for affine tetrahedral meshes;
  \item source-free Maxwell volume and surface operators;
  \item Hesthaven--Warburton strong-form and Poisson-bracket formulations;
  \item central and upwind Maxwell fluxes where mathematically supported;
  \item serial and Julia-threaded local execution backends;
  \item explicit Runge--Kutta methods of orders one through five;
  \item explicit partitioned symplectic Runge--Kutta (ESPRK) schemes of
        orders one through six;
  \item METIS element partition input;
  \item owned-element and one-layer face-halo mesh construction;
  \item MPI face orientation and nodal permutation handling;
  \item nonblocking exchange of the six Maxwell traces;
  \item six-field nonlinear PML damping without auxiliary variables;
  \item distributed energy reductions and distributed time integration;
  \item partition visualization, regression tests, convergence cases, and
        backend benchmarks.
\end{itemize}

\section{Supported execution modes}

\begin{description}[style=nextline]
  \item[Serial]
  One Julia process using \code{SerialBackend()}.

  \item[Threaded]
  One Julia process using \code{ThreadedBackend()} and a Julia thread count
  selected with \code{--threads=N} or \code{JULIA\_NUM\_THREADS=N}.

  \item[Distributed memory]
  Multiple Julia processes launched with \code{mpiexec}. Every rank owns a
  subset of tetrahedra and stores a one-face halo.

  \item[Hybrid MPI plus threads]
  The distributed constructor accepts a backend, so a threaded local backend
  can be selected per rank. This path should be validated on the target
  machine before production use; the primary MPI regression tests use the
  serial local backend.
\end{description}

\chapter{Mathematical Model}

\section{Source-free Maxwell equations}

For scalar, positive, elementwise-constant permittivity $\varepsilon_K$ and
permeability $\mu_K$, \pkg{} advances on each tetrahedron $K$
\begin{align}
  \varepsilon_K \frac{\partial \vect E}{\partial t}
    &= \nabla \times \vect H, \label{eq:maxwell-e}\\
  \mu_K \frac{\partial \vect H}{\partial t}
    &= -\nabla \times \vect E. \label{eq:maxwell-h}
\end{align}
The element wave speed, impedance, and admittance are
\begin{equation}
  c_K = \frac{1}{\sqrt{\varepsilon_K\mu_K}},
  \qquad
  Z_K = \sqrt{\frac{\mu_K}{\varepsilon_K}},
  \qquad
  Y_K = \frac{1}{Z_K}.
\end{equation}

The divergence constraints
\begin{equation}
  \nabla\cdot(\varepsilon\vect E)=0,
  \qquad
  \nabla\cdot(\mu\vect H)=0
\end{equation}
are not solved as separate equations. Their preservation depends on the
initial condition, mesh, spatial discretization, flux, and time integrator.

\section{Electromagnetic energy}

The continuous energy is
\begin{equation}
  \mathcal E(t)
  =
  \frac{1}{2}\int_\Omega
  \left(
    \varepsilon |\vect E|^2 + \mu |\vect H|^2
  \right)\dd \vect x.
\end{equation}
The code evaluates its DG approximation element by element using the reference
mass matrix and affine Jacobian determinant:
\begin{equation}
  \mathcal E_h
  =
  \frac{1}{2}
  \sum_{K}
  |J_K|
  \left[
    \varepsilon\sum_{\alpha\in\{x,y,z\}}
      \vect E_{\alpha,K}^{T}M\vect E_{\alpha,K}
    +
    \mu\sum_{\alpha\in\{x,y,z\}}
      \vect H_{\alpha,K}^{T}M\vect H_{\alpha,K}
  \right].
\end{equation}
In MPI runs only owned elements contribute locally, followed by an
\code{MPI.Allreduce} sum. Ghost elements are therefore not double counted.

\section{PEC boundary condition}

The perfect-electric-conductor condition is
\begin{equation}
  \vect n\times\vect E = \vect 0
  \qquad\text{on }\partial\Omega_{\mathrm{PEC}}.
\end{equation}
\pkg{} imposes it through a reflected exterior trace:
\begin{align}
  \vect E^+ &= -\vect E^- + 2(\vect n\cdot\vect E^-)\vect n,\\
  \vect H^+ &= \vect H^-.
\end{align}
This reverses the tangential electric field while retaining its normal
component. Boundary-condition selection is tag based. A typical registry is:

\begin{lstlisting}
registry = MaxwellBoundaryRegistry(
    Dict(10 => DiscoGMPI.MaxwellBC_PEC),
)
\end{lstlisting}

An unregistered boundary tag maps to \code{MaxwellBC\_None}; it does not
silently become PEC.

\section{PMC and absorbing boundary conditions}

The perfect-magnetic-conductor state reflects the tangential magnetic field
and retains the electric trace. It is selected with
\code{MaxwellBC\_PMC}. The \code{MaxwellBC\_Absorbing} state is a first-order,
impedance-matched characteristic condition: the incoming tangential
characteristic is set to zero using the adjacent element impedance. It is not
a PML and is most accurate for locally normally incident waves.

PMC reflection is supported by both the Hesthaven--Warburton and
Poisson-bracket surface operators, including distributed faces. For a PMC
cavity validation, the production driver uses electromagnetic duality:
\[
  \vect E_{\mathrm{PMC}}=Z\vect H_{\mathrm{PEC}},\qquad
  \vect H_{\mathrm{PMC}}=-\frac{1}{Z}\vect E_{\mathrm{PEC}},
  \qquad Z=\sqrt{\mu/\varepsilon}.
\]

\begin{lstlisting}
registry = MaxwellBoundaryRegistry(Dict(
    10 => MaxwellBC_PEC,
    20 => MaxwellBC_PMC,
    30 => MaxwellBC_Absorbing,
))
\end{lstlisting}

\section{Six-field nonlinear PML}
\label{sec:nonlinear-pml}

\pkg{} implements the primary nonlinear PML proposed by Abarbanel, Gottlieb,
and Hesthaven for time-dependent electromagnetics in three dimensions. The
implementation modifies the six physical Maxwell fields directly and
introduces no auxiliary unknowns. For positive isotropic, piecewise-constant
material coefficients $\varepsilon_K$ and $\mu_K$, the implemented elementwise
form is
\begin{align}
  \varepsilon_K\frac{\partial \vect E}{\partial t}
    &= \nabla\times\vect H
       + (\vect\sigma\odot\vect P_H)\times\vect H,
       \label{eq:nonlinear-pml-e}\\
  \mu_K\frac{\partial \vect H}{\partial t}
    &= -\nabla\times\vect E
       + (\vect\sigma\odot\vect P_E)\times\vect E,
       \label{eq:nonlinear-pml-h}
\end{align}
where $\odot$ denotes componentwise multiplication,
\begin{align}
  \vect P_H
    &=
    \frac{\vect E\times\vect H}
    {a\mu_K|\vect H|^2+(1-a)\varepsilon_K|\vect E|^2+\delta},\\
  \vect P_E
    &=
    -\frac{\vect E\times\vect H}
    {a\varepsilon_K|\vect E|^2+(1-a)\mu_K|\vect H|^2+\delta}.
\end{align}
The recommended and default parameter is $a=1/2$. The positive
regularization $\delta$, whose default is $10^{-12}$, prevents division by
zero where both fields vanish. Users should verify that the selected value is
small relative to the squared field scale of their problem.

For nonnegative damping coefficients
$\vect\sigma=(\sigma_x,\sigma_y,\sigma_z)$, the regularized PML contribution
to the pointwise energy balance is
\begin{equation}
  \frac{1}{2}\frac{\partial}{\partial t}
  \left(\varepsilon_K|\vect E|^2+\mu_K|\vect H|^2\right)
  =
  -\nabla\cdot(\vect E\times\vect H)
  -
  \sum_{i=1}^{3}
    \sigma_i(\vect E\times\vect H)_i^2
    \left(\frac{1}{D_H}+\frac{1}{D_E}\right),
\end{equation}
with
\[
  D_H=a\mu_K|\vect H|^2+(1-a)\varepsilon_K|\vect E|^2+\delta,\qquad
  D_E=a\varepsilon_K|\vect E|^2+(1-a)\mu_K|\vect H|^2+\delta.
\]
The local PML term is therefore nonpositive.

\paragraph{Sign convention.}
The magnetic source in \cref{eq:nonlinear-pml-h} follows Appendix A and the
energy identity in the 2006 paper. The sign printed in its vector equation
(2.10) is inconsistent with both. This choice is covered by a component-level
regression test and a discrete energy-decay test.

\paragraph{Reference.}
S.~Abarbanel, D.~Gottlieb, and J.~S.~Hesthaven,
``Non-Linear PML Equations for Time Dependent Electromagnetics in Three
Dimensions,'' \emph{Journal of Scientific Computing}, vol.~28, nos.~2--3,
2006, DOI:
\href{https://doi.org/10.1007/s10915-006-9072-1}
{10.1007/s10915-006-9072-1}.

\paragraph{Damping profiles.}
\code{polynomial\_pml\_sigma} constructs a one-sided profile that is zero at
the interior interface and rises to \code{sigma\_max} at the outer boundary:
\[
  \sigma(\xi)
  =
  \sigma_{\max}
  \left[
    \operatorname{clamp}
    \left(
      \frac{\xi-\xi_{\mathrm{interface}}}
           {\xi_{\mathrm{outer}}-\xi_{\mathrm{interface}}},
      0,1
    \right)
  \right]^m.
\]
Reversing the interface and outer-boundary coordinates produces a layer on
the opposite side. Independent functions may be supplied for
$\sigma_x$, $\sigma_y$, and $\sigma_z$.

\begin{lstlisting}
pml = build_maxwell_nonlinear_pml(
    distributed_dg;
    sigma_x = (x, y, z) -> polynomial_pml_sigma(
        x, 1.5, 2.0; sigma_max=12.0, degree=2
    ),
    a = 0.5,
    regularization = 1e-12,
)

scheme = explicit_partitioned_symplectic_rk_scheme(4; first_partition=:H)
work = MaxwellPartitionedRKWorkspace(U, scheme)
distributed_maxwell_nonlinear_pml_partitioned_symplectic_rk_step!(
    U, work, scheme, dt, distributed_dg, registry,
    PoissonBracketFormulation(MaxwellFlux_Alternating), pml;
    ε = 2.0,
    μ = 3.0,
)
\end{lstlisting}

The periodic wrapper is
\code{distributed\_periodic\_maxwell\_nonlinear\_pml\_partitioned\_symplectic\_rk\_step!}.
On MPI ranks, PML sources are added only to owned elements and ghost residuals
remain zero. Because no additional state variables or traces are introduced,
the existing six-component halo exchange is sufficient. Explicit-RK PML helper
functions remain available, but the production Poisson-bracket drivers keep the
requested ESPRK scheme when PML damping is active. The material-aware overloads
accept \code{MaxwellElementMaterials}; the scalar overloads accept
\code{epsilon}/\code{mu} through the usual Maxwell RHS coefficients.

\chapter{Tetrahedral DG Discretization}

\section{Mesh and approximation space}

The physical domain is partitioned into affine tetrahedra $K$. On each element,
every scalar field component is represented in
\begin{equation}
  \mathbb P^N(K)
  =
  \{p(x,y,z): \deg p\leq N\},
\end{equation}
with
\begin{equation}
  N_p = \frac{(N+1)(N+2)(N+3)}{6}
\end{equation}
volume nodes. A triangular face contains
\begin{equation}
  N_{fp} = \frac{(N+1)(N+2)}{2}
\end{equation}
nodes.

The reference tetrahedron has vertices
\[
(-1,-1,-1),\quad
(1,-1,-1),\quad
(-1,1,-1),\quad
(-1,-1,1).
\]
The implementation builds equispaced nodal points, an orthonormal polynomial
basis, a Vandermonde matrix, nodal derivative matrices, an exact polynomial
mass matrix, and face mass/lifting operators.

\section{Affine mapping and physical derivatives}

For an affine map $\vect x=\vect x_K(r,s,t)$, let $J_K$ denote its Jacobian.
Reference gradients are transformed by
\begin{equation}
  \nabla_{\vect x} u
  =
  J_K^{-T}\nabla_{(r,s,t)}u.
\end{equation}
The physical derivative matrices $D_x,D_y,D_z$ and weak derivative matrices
\begin{equation}
  S_x = M D_x,\qquad S_y=M D_y,\qquad S_z=M D_z
\end{equation}
are precomputed for each tetrahedron. The Poisson-bracket formulation also
uses $S_x^T,S_y^T,S_z^T$.

\section{Topology, traces, and lifting}

Faces are identified by sorted triples of global vertex IDs. A face appearing
once is a boundary face; a face appearing twice is an interior face. More than
two adjacent tetrahedra is treated as a non-manifold error.

For every interior face, the DG trace map stores:
\begin{itemize}[leftmargin=*]
  \item minus and plus element IDs;
  \item local face IDs;
  \item face-node indices;
  \item the plus-to-minus nodal permutation;
  \item the outward minus-side normal and face area.
\end{itemize}

Surface residuals are projected through the face mass matrix and lifted into
the element volume. Conceptually, a face correction $\vect f$ contributes
\begin{equation}
  M_K^{-1}M_{f,K}\vect f
\end{equation}
to the nodal right-hand side, with the physical face area and element Jacobian
included by the implementation.

\section{Hesthaven--Warburton formulation}

The strong-form volume terms directly approximate
\begin{align}
  \dot{\vect E}_K &= \frac{1}{\varepsilon}
    (\nabla_h\times\vect H)_K + \text{surface correction},\\
  \dot{\vect H}_K &= -\frac{1}{\mu}
    (\nabla_h\times\vect E)_K + \text{surface correction}.
\end{align}

Let $\jump{\vect E}=\vect E^+-\vect E^-$ and
$\jump{\vect H}=\vect H^+-\vect H^-$. The central correction used by the
code is
\begin{align}
  \vect f_E^{\mathrm c}
    &= \frac{1}{2}\vect n\times\jump{\vect H},\\
  \vect f_H^{\mathrm c}
    &= -\frac{1}{2}\vect n\times\jump{\vect E}.
\end{align}
The upwind flux adds tangential penalties:
\begin{align}
  \vect f_E^{\mathrm up}
    &= \vect f_E^{\mathrm c}
       -\frac{Y}{2}\vect n\times
        \left(\vect n\times\jump{\vect E}\right),\\
  \vect f_H^{\mathrm up}
    &= \vect f_H^{\mathrm c}
       -\frac{Z}{2}\vect n\times
        \left(\vect n\times\jump{\vect H}\right).
\end{align}

Select the formulation with:

\begin{lstlisting}
central = HesthavenWarburtonFormulation(MaxwellFlux_Central)
upwind  = HesthavenWarburtonFormulation(MaxwellFlux_Upwind)
\end{lstlisting}

The central flux is nondissipative in the ideal compatible setting. The
upwind flux introduces numerical dissipation and is normally preferred when
robust damping of unresolved jumps is more important than exact semidiscrete
energy conservation.

\section{Poisson-bracket formulation}

The Poisson-bracket implementation is a partitioned weak-operator
discretization. The electric update uses weak derivative matrices
$S_x,S_y,S_z$, while the magnetic update uses their transposes. This pairing
constructs a discrete skew structure and supports energy-compatible
partitioned time stepping.

For an interior face, the implemented corrections can be summarized as
\begin{align}
  \vect f_E^{\mathrm{PB}}
    &= -\frac{1}{2\varepsilon}
       \vect n\times(\vect H^- - \vect H^+),\\
  \vect f_H^{\mathrm{PB}}
    &= -\frac{1}{2\mu}
       \vect n\times(\vect E^- + \vect E^+).
\end{align}

Only the central flux is supported:

\begin{lstlisting}
formulation = PoissonBracketFormulation()
\end{lstlisting}

Attempting to combine the Poisson-bracket formulation with the upwind flux
raises an error because the upwind penalty is dissipative and does not define
the implemented partitioned Poisson operator.

\chapter{Time Integration}

\section{Explicit Runge--Kutta methods}

For a semidiscrete system $\dot U=R(U)$, an explicit Runge--Kutta method uses
\begin{align}
  U^{(i)} &= U^n + \Delta t\sum_{j<i}a_{ij}K_j,\\
  K_i &= R(U^{(i)}),\\
  U^{n+1} &= U^n + \Delta t\sum_i b_iK_i.
\end{align}

\begin{table}[htbp]
\centering
\caption{Explicit Runge--Kutta schemes available through
\code{explicit\_rk\_scheme(order)}.}
\begin{tabular}{clc}
\toprule
Order & Scheme & Stages \\
\midrule
1 & Forward Euler & 1 \\
2 & Explicit midpoint & 2 \\
3 & Classical third order & 3 \\
4 & Classical fourth order & 4 \\
5 & Dormand--Prince fifth-order update & 7 \\
\bottomrule
\end{tabular}
\end{table}

The Dormand--Prince implementation uses the fifth-order update only. Adaptive
step-size control and the embedded fourth-order estimator are not exposed.

\section{Explicit partitioned symplectic methods}

The Maxwell state is divided into electric and magnetic partitions. At every
ESPRK stage, one partition is updated using its weight, the right-hand side is
recomputed, and the complementary partition is updated using its own weight.
Orders one through six are available:

\begin{lstlisting}
scheme = explicit_partitioned_symplectic_rk_scheme(
    4;
    first_partition = :H,
)
\end{lstlisting}

For \code{PoissonBracketFormulation}, the magnetic partition must be advanced
first:

\begin{lstlisting}
formulation = PoissonBracketFormulation()

run_maxwell_partitioned_symplectic_time_steps!(
    U,
    dg,
    registry,
    formulation;
    psrk_order = 4,
    first_partition = :H,
    dt = dt,
    nsteps = nsteps,
)
\end{lstlisting}

Using the conventional explicit Runge--Kutta driver with the Poisson-bracket
formulation is rejected by the high-level API.

\section{CFL estimate}

The code defines the element characteristic length
\begin{equation}
  h_K = \frac{3V_K}{A_K},
\end{equation}
where $V_K$ is the tetrahedron volume and $A_K$ its total surface area. The
recommended estimate is
\begin{equation}
  \Delta t
  =
  \mathrm{CFL}
  \frac{\min_K h_K}{(2N+1)c}.
\end{equation}
It is obtained with:

\begin{lstlisting}
dt, sizes = estimate_maxwell_dt(
    mesh,
    dg.geometry,
    dg.ref;
    CFL = 0.10,
)
\end{lstlisting}

This expression is an estimate, not a proof of stability for every mesh,
formulation, flux, and RK scheme. Production studies should include a
step-size sensitivity check.

\chapter{Distributed-Memory Design}

\section{Element ownership and face halos}

An element partition vector assigns every global tetrahedron to a zero-based
MPI rank:
\begin{equation}
  p_e\in\{0,\ldots,P-1\}.
\end{equation}
For rank $r$, \pkg{} stores:

\begin{itemize}[leftmargin=*]
  \item every element for which $p_e=r$ as \emph{owned};
  \item every off-rank tetrahedron sharing a complete face with an owned
        element as a \emph{ghost};
  \item the nodes required by those owned and ghost elements;
  \item global-to-local and local-to-global maps;
  \item ownership, material IDs, face neighbors, volumes, and barycenters;
  \item one communication record per neighboring rank.
\end{itemize}

Only a one-face halo is needed because the Maxwell DG surface operator couples
elements only through face traces.

\section{Face orientation}

A triangular face admits six vertex permutations. For each inter-rank face,
the distributed mesh records the orientation code that maps the neighbor
ordering to the local ordering. The trace layer converts face nodes to
barycentric coordinates and precomputes one nodal permutation for each of the
six orientations. Received plus traces are therefore presented in the same
physical point ordering as the local minus trace.

This permutation step is essential for polynomial order $N>1$: matching only
the three vertices is insufficient because edge and interior face nodes must
also be reordered.

\section{Maxwell communication}

At each right-hand-side evaluation:

\begin{enumerate}[leftmargin=*]
  \item The six owned face traces
        $(E_x,E_y,E_z,H_x,H_y,H_z)$ are packed for every neighbor.
  \item All nonblocking receives are posted.
  \item All nonblocking sends are posted.
  \item \code{MPI.Waitall} completes the exchange.
  \item Received values are unpacked into the corresponding ghost face nodes.
  \item The local DG right-hand side is evaluated.
  \item Every ghost-element right-hand-side column is set to zero, ensuring
        that time integration updates owned elements only.
\end{enumerate}

For a neighbor with $F_{rn}$ interface faces, the message contains
\begin{equation}
  6N_{fp}F_{rn}
\end{equation}
double-precision values per right-hand-side evaluation.

\paragraph{Current computation model.}
The local DG kernel currently evaluates owned and stored ghost elements before
zeroing ghost residuals. Communication volume is already trace-only, but a
future optimization can avoid unnecessary ghost volume work and overlap
communication with owned volume calculations.

\section{Root-only mesh distribution}

The scalable constructor keeps the global mesh and partition vector only on a
designated root rank. Root builds each rank's owned-plus-halo package and sends
that serialized package to the destination. Non-root ranks never construct or
retain the complete global mesh.

\begin{lstlisting}
using MPI
using DiscoGMPI

MPI.Init()
comm = MPI.COMM_WORLD
rank = MPI.Comm_rank(comm)
nranks = MPI.Comm_size(comm)

root_mesh = rank == 0 ? read_vtu_mesh("mesh.vtu") : nothing
root_partition = if rank == 0
    read_metis_epart("mesh.mesh.epart.$nranks")
else
    nothing
end

ddg = build_distributed_dg_from_root(
    root_mesh,
    root_partition,
    2;
    comm = comm,
    root = 0,
)

MPI.Barrier(comm)
MPI.Finalize()
\end{lstlisting}

The file-based overload performs both reads only on root:

\begin{lstlisting}
ddg = build_distributed_dg_from_root(
    "mesh.vtu",
    "mesh.mesh.epart.4",
    2;
    comm = MPI.COMM_WORLD,
)
\end{lstlisting}

All ranks must call the constructor collectively. Root validation errors are
broadcast so that malformed input fails collectively rather than leaving
worker ranks blocked.

\section{Replicated constructor}

When a global \code{RawVTUMesh} and partition vector already exist on every
rank, the compatibility constructor remains available:

\begin{lstlisting}
ddg = build_distributed_dg(
    global_mesh,
    elem_to_rank,
    order;
    comm = MPI.COMM_WORLD,
)
\end{lstlisting}

The root-only constructor is preferable for memory scaling on non-root ranks.
Root still holds the complete input mesh during distribution.

\section{RawVTUMesh format}

The primary solver mesh container is:

\begin{lstlisting}
RawVTUMesh(

    tets,          # 4 x number_of_tetrahedra, Int
    tris,          # 3 x number_of_boundary_triangles, Int
    tet_cell_ids,
    tri_cell_ids,
    cell_data,
)
\end{lstlisting}

Connectivity uses Julia's one-based indexing. The XML VTU reader accepts
tetrahedral volume cells and triangular surface cells and ignores unsupported
cell types.

\section{Boundary and material tags}

By default, \code{DGDiscretization} looks for cell data named
\code{boundary\_id}. The array is indexed by the original VTK cell IDs;
\code{tri\_data(mesh, "boundary\_id")} extracts its surface-triangle values.

The distributed constructors also accept:

\begin{lstlisting}
boundary_tag_name = "boundary_id"
material_tag_name = "region_id"
\end{lstlisting}

Material IDs are preserved in the distributed topology and can be converted
to element coefficients:

\begin{lstlisting}
materials = maxwell_element_materials(
    distributed_dg,
    Dict(
        1 => MaxwellMaterial(1.0, 1.0),
        2 => MaxwellMaterial(4.0, 2.0),
    ),
)
\end{lstlisting}

The material-aware Maxwell overloads accept \code{materials} as a positional
argument. Central fluxes use the coefficient of the updated element. The
Hesthaven--Warburton upwind interface solver uses side-dependent impedance and
admittance. Coefficients are currently isotropic and constant inside each
tetrahedron.

\section{Distributed periodic boundaries}

\code{build\_distributed\_periodic\_maxwell\_exchange} gathers only owned
periodic boundary descriptors, pairs shifted centroids and DG face nodes, and
constructs directed rank-local faces. Remote periodic traces use a separate
nonblocking MPI exchange; same-rank partners are read directly.

\begin{lstlisting}
periodic = build_distributed_periodic_maxwell_exchange(
    distributed_dg,
    default_unit_box_periodic_specs();
    materials = materials,
)
\end{lstlisting}

Periodic boundary tags must map to \code{MaxwellBC\_None} in the ordinary
boundary registry. When material-aware periodic fluxes are used, pass
\code{materials} while constructing the exchange so remote partner
coefficients are recorded.

\section{Mesh-quality requirements}

\begin{itemize}[leftmargin=*]
  \item Tetrahedra must have four valid, distinct nodes.
  \item Every interior face must be shared by exactly two tetrahedra.
  \item Boundary triangles must match tetrahedral exterior faces.
  \item Volumes and face areas must be positive.
  \item The partition vector length must equal the tetrahedron count.
  \item Every partition ID must lie in \code{0:nranks-1}.
  \item Every MPI rank should normally own at least one element.
\end{itemize}

\section{Distributed PEC, PMC, and nonlinear-PML cavity driver}

The production driver
\code{examples/distributed\_poisson\_bracket\_maxwell.jl} uses PEC boundaries
by default. Select PMC walls with:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_poisson_bracket_maxwell.jl \
  --boundary-condition=pmc
\end{lstlisting}
Without PML, the driver uses the requested H-first ESPRK method and compares
against the corresponding PEC or dual PMC cavity eigenmode.

Add a polynomial nonlinear PML at all six coordinate bounds with:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_poisson_bracket_maxwell.jl \
  --boundary-condition=pmc \
  --pml-width=0.2 \
  --pml-sigma-max=12 \
  --pml-degree=2 \
  --esprk-order=4
\end{lstlisting}
Both \code{--pml-width} and \code{--pml-sigma-max} must be positive to enable
the PML, or both zero to disable it. The width must be smaller than half the
shortest global domain extent. PML runs support scalar \code{--epsilon} and
\code{--mu} values and keep the requested H-first ESPRK method.
The cavity mode remains in the output as an undamped reference; it is not an
exact solution of the damped problem.

\subsection{Diagnostics and production output}

The default output directory is
\code{output/distributed\_poisson\_bracket/}. The driver writes the same
production artifact family as the periodic driver:
\begin{itemize}[leftmargin=*]
  \item \code{diagnostics/energy.csv}: DG mass-matrix electric, magnetic, and
        total energy;
  \item \code{diagnostics/quadrature\_diagnostics.csv}:
        independent-cubature field and energy errors, optical chirality,
        electric and magnetic charge, and linear and angular momentum;
  \item \code{fields.pvd} and \code{fields/fields\_stepNNNNNNNN.pvtu}:
        ParaView time series;
  \item \code{diagnostics/integration\_points\_rankNNNN.csv}: final
        integration-point numerical and analytical values, including pointwise
        chirality;
  \item \code{config/run\_metadata.toml},
        \code{config/resolved\_config.toml}, and
        \code{config/partition\_metadata.csv};
  \item \code{input/input\_manifest.toml};
  \item \code{checkpoints/stepNNNNNNNN/}: checksummed rank-local restart data;
  \item \code{status.toml}: current run status.
\end{itemize}
For backward compatibility, the run root also contains symlinks named
\code{energy.csv}, \code{quadrature\_diagnostics.csv},
\code{run\_metadata.toml}, and \code{partition\_metadata.csv}.

At every cubature point, the driver evaluates
\[
  \chi =
  \frac{1}{2}\left(
    \varepsilon\,\vect E\cdot\nabla\times\vect E
    +\mu\,\vect H\cdot\nabla\times\vect H
  \right).
\]
The numerical curls use the physical element derivative operators. The exact
cavity curls are evaluated analytically for both PEC and dual PMC modes. In
PML runs the same undamped cavity field remains the diagnostic reference, so
field, energy, and chirality errors should be interpreted as reference
errors, not as exact damped-solution errors.

The ParaView output writes each owned DG element as a VTK Lagrange tetrahedron
containing every DG node. The rank-local VTU pieces include
\code{ElectricField}, \code{MagneticField}, \code{ExactElectricField},
\code{ExactMagneticField}, \code{ElectricFieldError}, and
\code{MagneticFieldError}, plus field magnitudes, global element IDs, owner
rank, polynomial order, and physical time.

\section{Distributed periodic Poisson-bracket traveling wave}

The production periodic driver is:
\begin{lstlisting}[language=bash]
examples/distributed_periodic_poisson_bracket_maxwell.jl
\end{lstlisting}
By default it uses the legacy VTK mesh
\code{examples/meshes/periodic\_box\_2x1x1\_nx4.vtk}, whose domain is
\[
  \Omega=[0,2]\times[0,1]\times[0,1].
\]
The mesh contains four structured hexahedral intervals in the $x$ direction,
each divided into six conforming tetrahedra, for a total of 24 tetrahedra.
The periodic physical-surface tags are
\begin{center}
\begin{tabular}{ccc}
\toprule
Direction & Minus tag & Plus tag \\
\midrule
$x$ & 1 & 2 \\
$y$ & 3 & 4 \\
$z$ & 5 & 6 \\
\bottomrule
\end{tabular}
\end{center}
The corresponding plus-to-minus translations are
$(-2,0,0)$, $(0,-1,0)$, and $(0,0,-1)$. These tags must map to
\code{MaxwellBC\_None} in the ordinary boundary registry because the periodic
surface operator handles them separately.

The domain dimensions are not hard-coded requirements. For a conforming
tetrahedral mesh of an axis-aligned box whose opposite surface triangulations
match under translation, the driver infers
\[
  (x_{\min},y_{\min},z_{\min}),\qquad
  (x_{\max},y_{\max},z_{\max})
\]
from the mesh coordinates. It reconstructs boundary tags 1 through 6 from the
six coordinate planes and derives the periodic translations from
$L_x=x_{\max}-x_{\min}$, $L_y=y_{\max}-y_{\min}$, and
$L_z=z_{\max}-z_{\min}$. A separate domain-bounds command-line option is
intentionally unnecessary because the mesh is the authoritative geometry
description.

\subsection{Generating meshes with a configurable x resolution}

The generator
\code{examples/meshes/generate\_periodic\_box\_2x1x1\_nx4.jl} accepts the
number of structured cells in the $x$ direction through \code{--nx}. Each
cell is decomposed into six tetrahedra. For example:
\begin{lstlisting}[language=bash]
julia --project=. \
  examples/meshes/generate_periodic_box_2x1x1.jl \
  --nx=8
\end{lstlisting}
This creates
\code{examples/meshes/periodic\_box\_2x1x1\_nx8.vtk}, with 36 points and
48 tetrahedra. The boundary tags remain $1/2$, $3/4$, and $5/6$ for the
$x$, $y$, and $z$ periodic pairs. The general mesh sizes are
\[
  N_{\mathrm{points}}=4(n_x+1),\qquad
  N_{\mathrm{tet}}=6n_x.
\]
An explicit output path may be selected with \code{--output=PATH}. If
\code{--nx} is omitted, the default value is four and the generated VTK file
is identical to the supplied \code{nx4} mesh.

The analytical solution is
\begin{align}
  \vect E(\vect x,t)
    &= \left(0,0,-\frac{kH_0}{\omega\varepsilon_0}\right)
       \sin(kx-\omega t),\\
  \vect H(\vect x,t)
    &= (0,H_0,0)\sin(kx-\omega t),
\end{align}
with
\[
  k=\omega=2\pi,\qquad
  H_0=1,\qquad
  \varepsilon_0=\mu_0=1.
\]
Thus the implemented fields are
\[
  \vect E=(0,0,-\sin(2\pi x-2\pi t)),\qquad
  \vect H=(0,\sin(2\pi x-2\pi t),0).
\]
On a translated box, the phase uses $x-x_{\min}$. The wave number can be
selected with \code{--wave-number=K}; the angular frequency is
$\omega=K/\sqrt{\varepsilon_0\mu_0}$. The driver requires
\[
  \frac{K L_x}{2\pi}\in\mathbb{N},
\]
which ensures that the analytical field is periodic across the inferred
x-boundaries. The default remains $K=2\pi$.

Run two MPI partitions with:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --partitions=2
\end{lstlisting}

The value of \code{--partitions} must equal the number of MPI ranks.
\code{--partitions=N} specifies a count, while \code{--partition=PATH}
selects an existing METIS element-partition file. In particular,
\code{--partition=2} means ``read the file named \code{2}''; it does not
request two partitions.

The generated \code{nx8} mesh can be run on two ranks with:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --partitions=2 \
  --mesh=examples/meshes/periodic_box_2x1x1_nx8.vtk \
  --repartition \
  --rebuild-distributed-mesh \
  --order=2 \
  --esprk-order=3 \
  --final-time=10.0 \
  --cfl=0.5
\end{lstlisting}
The default partition path and distributed-mesh cache contain the source mesh
basename, so \code{nx4} and \code{nx8} artifacts do not collide. The
\code{--repartition} and \code{--rebuild-distributed-mesh} options are
required when replacing a mesh while retaining the same filename.

For example, an unstructured mesh with bounds
$[0,1]\times[0,0.25]\times[0,0.25]$ can be run directly:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --mesh=examples/meshes/periodic_box_unstructured.vtk \
  --partitions=2 \
  --repartition \
  --rebuild-distributed-mesh \
  --order=4 \
  --esprk-order=5 \
  --cfl=0.8 \
  --final-time=1.0
\end{lstlisting}
Here the default $K=2\pi$ gives one wavelength across the unit x extent.

A four-way partition is generated and run with:
\begin{lstlisting}[language=bash]
mpiexec -n 4 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --partitions=4 --repartition
\end{lstlisting}

\subsection{Automatic METIS partitioning}

When \code{--partition} is omitted, rank zero:
\begin{enumerate}[leftmargin=*]
  \item reads the legacy VTK tetrahedra;
  \item calls \code{write\_metis\_mesh\_from\_vtk};
  \item runs the installed \code{mpmetis} executable for the requested number
        of partitions;
  \item validates the zero-based element partition;
  \item prepares the rank-local owned-plus-halo mesh cache.
\end{enumerate}
Generated partitions are stored under \code{output/partitions/}. Use
\code{--repartition} to replace an existing partition and
\code{--rebuild-distributed-mesh} to recreate the rank-local cache. An
existing partition may be selected explicitly:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --partitions=2 \
  --partition=output/partitions/periodic_box_2x1x1_nx4.mesh.epart.2
\end{lstlisting}

\subsection{Polynomial-order requirement}

This driver requires DG order $N\geq2$. For $N=1$ on the default
\code{nx4} mesh, all DG nodes have $x\in\{0,0.5,1,1.5,2\}$, where
$\sin(2\pi x)=0$. Nodal interpolation would therefore produce an identically
zero initial field even though the continuous analytical wave is nonzero
inside each interval. The driver rejects \code{--order=1}.

\subsection{Diagnostics and production output}

The default output directory is
\code{output/distributed\_periodic\_poisson\_bracket/}. The driver preserves
the production I/O behavior of the PEC Poisson-bracket case:
\begin{itemize}[leftmargin=*]
  \item \code{diagnostics/energy.csv}: DG mass-matrix electric, magnetic, and
        total energy;
  \item \code{diagnostics/quadrature\_diagnostics.csv}:
        independent-cubature field and energy errors, optical chirality,
        electric and magnetic charge, and linear and angular momentum;
  \item \code{fields.pvd} and \code{fields/fields\_stepNNNNNNNN.pvtu}:
        ParaView time series;
  \item \code{diagnostics/integration\_points\_rankNNNN.csv}: final
        integration-point numerical and analytical values;
  \item \code{config/run\_metadata.toml},
        \code{config/resolved\_config.toml}, and
        \code{config/partition\_metadata.csv};
  \item \code{input/input\_manifest.toml};
  \item \code{checkpoints/stepNNNNNNNN/}: checksummed rank-local restart data;
  \item \code{status.toml}: current run status.
\end{itemize}
For backward compatibility, the run root also contains symlinks named
\code{energy.csv}, \code{quadrature\_diagnostics.csv},
\code{run\_metadata.toml}, and \code{partition\_metadata.csv}.

At every cubature point, the driver evaluates the optical chirality density
\[
  \chi =
  \frac{1}{2}\left(
    \varepsilon\,\vect E\cdot\nabla\times\vect E
    +\mu\,\vect H\cdot\nabla\times\vect H
  \right).
\]
The curls are formed with the physical element derivative operators. The
diagnostics file stores the distributed integral of $\chi$, its analytical
value and error, and the numerical, analytical, and error $L^2$ norms of its
density. The rank-local integration-point files store the corresponding
pointwise densities. For the linearly polarized traveling wave used here,
the analytical optical chirality is identically zero.

Restart requires the same rank count, partition, and DG order:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --partitions=2 \
  --restart=output/distributed_periodic_poisson_bracket/checkpoints/step00000100 \
  --final-time=0.5
\end{lstlisting}

The implementation has been exercised with automatic two-way and four-way
METIS partitions. In the short regression runs, the centered
Poisson-bracket/ESPRK discretization preserved discrete total energy to
roundoff and the integrated electric and magnetic charges remained near
machine precision.

\section{Distributed nonlinear PML pulse}

The executable example
\code{examples/distributed\_nonlinear\_pml\_maxwell.jl} demonstrates the
formulation from \cref{sec:nonlinear-pml}. It generates
$[0,2]\times[0,1]\times[0,1]$ in memory, partitions its $6n_x$ tetrahedra by
$x$ slab, uses periodic boundaries in $y$ and $z$, and places polynomial
nonlinear PML layers at both $x$ ends. The initial condition is a
right-traveling, linearly polarized Gaussian pulse:
\[
  \vect E=(0,0,g(x)),\qquad
  \vect H=(0,-g(x),0).
\]
The default Hesthaven--Warburton upwind flux supplies a robust outer
termination beyond the PML.

\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_nonlinear_pml_maxwell.jl \
  --nx=8 --order=2 --rk-order=4 \
  --final-time=1.3 --cfl=0.15 \
  --pml-width=0.5 --sigma-max=12 \
  --sigma-degree=2
\end{lstlisting}

Important options are:
\begin{description}[style=nextline]
  \item[\code{--nx}]
  Number of structured $x$ cells; there are six tetrahedra per cell.
  It must be at least the MPI rank count.

  \item[\code{--pml-width}]
  Width of each $x$-directed layer. It must lie in $(0,1)$ so the two
  layers do not overlap.

  \item[\code{--sigma-max} and \code{--sigma-degree}]
  Peak damping and polynomial profile degree.

  \item[\code{--regularization}]
  Positive $\delta$ added to both nonlinear denominators.

  \item[\code{--energy-every}]
  Number of time steps between global-energy samples.
\end{description}

Rank zero writes
\code{output/distributed\_nonlinear\_pml/energy.csv}, containing the time,
step, electric energy, magnetic energy, total energy, and total-to-initial
energy ratio. A representative two-rank run with the command above reduced
the ratio to approximately $1.25\times10^{-2}$ by $t=1.3$, with no increase
between sampled energy values.

\section{Empty-domain incident-wave PML gate}

The first validation-sequence gate for the nonlinear PML is
\code{examples/validate\_empty\_domain\_incident\_pml.jl}. It is a thin
release-gate wrapper around the production Poisson-bracket PML validation
driver, so it exercises the same H-first ESPRK and nonlinear PML code path.
The default case launches the same right-going sine-modulated Gaussian pulse
in an otherwise empty cuboid, uses periodic boundaries in $y$ and $z$, and
places nonlinear PML layers at the two $x$ boundaries. The default mesh is
\code{examples/meshes/periodic\_box\_structured\_nx16\_ny8\_nz8.vtk}; with
$\lambda_0=0.5$ this gives four $x$-elements per central wavelength.

\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/validate_empty_domain_incident_pml.jl \
  --max-reflection-ratio=1e-2 \
  --max-final-energy-ratio=2.5e-1
\end{lstlisting}

The pass/fail quantities are computed from the quadrature diagnostics written
by the production PML driver:
\begin{description}[style=nextline]
  \item[\code{reflection\_ratio}]
  Maximum left-monitor energy after the configured reflection-start time,
  normalized by the initial total electromagnetic energy. This is the main
  empty-domain PML reflection metric.

  \item[\code{final\_energy\_ratio}]
  Final total electromagnetic energy divided by the initial total energy.
  Since the PML is dissipative, the release gate requires this ratio to stay
  below \code{--max-final-energy-ratio}.

  \item[\code{max\_energy\_growth}]
  Numerical tolerance for energy growth above the initial energy. The PML
  path should not generate energy, even though it is not energy-conservative.
\end{description}

The root output directory is
\code{output/validation\_sequence/empty\_domain\_incident\_pml}. It contains
the normal per-case PML run directories plus
\code{empty\_domain\_incident\_pml\_summary.csv} and
\code{empty\_domain\_incident\_pml\_summary.json}. The CSV and JSON files are
machine-readable release-gate summaries. The executable exits with a nonzero
status when any case fails. All options accepted by
\code{distributed\_poisson\_bracket\_pml\_validation.jl} can be passed to this
gate and override the defaults, including \code{--mesh}, \code{--flux},
\code{--pml-width}, \code{--sigma-max}, \code{--sigma-degree},
\code{--energy-every}, and \code{--paraview-every}.

\section{PEC sphere boundary-residual gate}

The second validation-sequence gate checks the incident-aware PEC condition on
the metallic sphere. The numerical solution is stored as the scattered field,
so the physical boundary condition is evaluated on the total field
\[
  \vect E_{\mathrm{tot}}
  =
  \vect E_{\mathrm{scat}}+\vect E_{\mathrm{inc}},
  \qquad
  \vect n\times\vect E_{\mathrm{tot}}=\vect 0
  \quad\text{on }\Gamma_{\mathrm{PEC}}.
\]
The driver computes the surface diagnostic
\[
  \left\|\vect n\times\vect E_{\mathrm{tot}}\right\|_{L^2(\Gamma_{\mathrm{PEC}})}
  =
  \left(
    \int_{\Gamma_{\mathrm{PEC}}}
    \left|\vect n\times\vect E_{\mathrm{tot}}\right|^2\,dS
  \right)^{1/2},
\]
using the same owned sphere-face quadrature infrastructure used by the RCS
surface-current diagnostic. It also reports the RMS residual, the RMS residual
divided by the incident amplitude, and the maximum sampled pointwise residual.

\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/validate_pec_sphere_boundary_residual.jl \
  --max-final-relative-rms=1e-1
\end{lstlisting}

The scattering run writes
\code{diagnostics/pec\_boundary\_residual.csv}. The validation gate writes
\code{pec\_sphere\_boundary\_residual\_summary.csv} and
\code{pec\_sphere\_boundary\_residual\_summary.json} in
\code{output/validation\_sequence/pec\_sphere\_boundary\_residual}. The
primary pass/fail metric is \code{final\_relative\_rms}, controlled by
\code{--max-final-relative-rms}. Additional optional gates are
\code{--max-final-l2}, \code{--max-final-relative-max}, and
\code{--max-sampled-relative-rms}. The sampled maximum includes the startup
transient unless the user selects diagnostics and final time so that startup
samples are excluded from the gate. By default this gate uses
\code{examples/meshes/metallic\_sphere\_scattering\_validation.vtk}, a coarse
validation mesh with roughly $2.9\times 10^4$ tetrahedra. The larger
\code{metallic\_sphere\_scattering.vtk} mesh has roughly
$3.6\times 10^5$ tetrahedra and should be reserved for production
scattering/RCS studies.

\end{lstlisting}

\section{Coarse PEC-sphere RCS gate}

The next validation-sequence step exercises the near-to-far RCS extraction on
the coarse metallic-sphere mesh and compares the angular samples with the exact
PEC Mie-series solution. The executable is
\code{examples/validate\_coarse\_sphere\_rcs.jl}. It is intentionally a coarse
release gate: by default it checks that the RCS pipeline runs, that the
accumulated Fourier samples are finite and nonzero, and that a
machine-readable Mie comparison is written.
The implementation details are documented in
\code{docs/numerics/rcs\_metallic\_sphere.md}.

The production scattering driver is
\code{examples/distributed\_metallic\_sphere\_scattering.jl}. It solves for
the scattered field of a PEC sphere illuminated by a plane wave propagating in
the $+z$ direction with $x$-polarized electric field,
\[
  \vect E_{\rm inc}
  =
  A\hat{\vect x}\cos(kz-\omega t),
  \qquad
  \vect H_{\rm inc}
  =
  \frac{A}{Z}\hat{\vect y}\cos(kz-\omega t),
\]
where $k=2\pi/\lambda$, $\omega=ck$, $c=(\epsilon\mu)^{-1/2}$, and
$Z=(\mu/\epsilon)^{1/2}$. The numerical unknown is the scattered field and the
physical field is reconstructed as
\[
  \vect E_{\rm tot}=\vect E_{\rm scat}+\vect E_{\rm inc},
  \qquad
  \vect H_{\rm tot}=\vect H_{\rm scat}+\vect H_{\rm inc}.
\]
The incident-aware PEC boundary condition on the sphere is
\[
  \vect n\times\vect E_{\rm tot}=\vect 0,
  \qquad
  \vect n\times\vect E_{\rm scat}
  =
  -\vect n\times\vect E_{\rm inc}.
\]

When RCS extraction is enabled, the driver forms the PEC equivalent surface
current
\[
  \vect J_s = \vect n\times\vect H_{\rm tot}
\]
and accumulates the near-to-far integral
\[
  \vect I(\hat{\vect r},t)
  =
  \int_{\Gamma_{\rm PEC}}
  \vect J_s(\vect x,t)
  \exp\!\left(-i k\,\hat{\vect r}\cdot\vect x\right)\,dS.
\]
The time-domain integral is converted to a phasor through a Hann-windowed
Fourier extraction over
$[\code{--rcs-start-time},\code{--final-time}]$. The reconstructed transverse
far field is then normalized as
\[
  \sigma(\theta,\phi)
  =
  4\pi
  \frac{
    \left|\vect E^\infty_{\rm scat}(\theta,\phi)\right|^2
  }{
    \left|\vect E_{\rm inc}\right|^2
  }.
\]

\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/validate_coarse_sphere_rcs.jl
\end{lstlisting}

The default run uses
\code{examples/meshes/metallic\_sphere\_scattering\_validation.vtk},
DG order $p=1$, ESPRK order $2$, \code{--enable-rcs}, a $37$-point polar
sampling grid at $\phi=0$, and disables ParaView snapshots. The scattering
driver writes the numerical far-field table
\code{diagnostics/rcs.csv}. The validation gate writes
\code{diagnostics/coarse\_mie\_rcs\_comparison.csv}, with one row per
observation direction and columns for
\[
  \sigma_h(\theta,\phi),\qquad
  \sigma_{\mathrm{Mie}}(\theta,\phi),\qquad
  \left|\sigma_h-\sigma_{\mathrm{Mie}}\right|,\qquad
  \frac{\left|\sigma_h-\sigma_{\mathrm{Mie}}\right|}{\pi a^2},
\]
together with relative and dB errors. It also writes
\code{coarse\_sphere\_rcs\_summary.csv} and
\code{coarse\_sphere\_rcs\_summary.json} in
\code{output/validation\_sequence/coarse\_sphere\_rcs}.

The default pass/fail criteria are deliberately loose because a short coarse
run is not a resolved RCS benchmark. The gate requires finite RCS rows, at
least one accumulated sample, positive window weight, and
\code{max\_numerical\_rcs >= --min-max-rcs}. The default
\code{--min-max-rcs} is $10^{-12}$. Stricter quantitative checks can be enabled
with \code{--max-absolute-normalized-error},
\code{--max-rms-relative-error}, and \code{--max-db-error}. Those thresholds
should be selected only after choosing a resolved mesh, final time, and
Fourier-window start time.

The RCS command-line controls have the following meaning:
\begin{description}[style=nextline]
  \item[\code{--rcs-start-time}]
  First time included in the Fourier extraction. For quantitative Mie
  comparison, this should be after the startup transient has left the near
  field. Setting it equal to the final time is useful only for one-step smoke
  tests.

  \item[\code{--rcs-every}]
  Time-step interval between RCS samples. Small values increase sampling but
  also increase surface-integration overhead. Long production runs usually do
  not require \code{--rcs-every=1}.

  \item[\code{--rcs-theta-count},
        \code{--rcs-theta-min-degrees},
        \code{--rcs-theta-max-degrees}]
  Polar scattering-angle grid. The default coarse gate uses $37$ samples over
  $[0^\circ,180^\circ]$.

  \item[\code{--rcs-phi-degrees}]
  Comma-separated azimuth angles. The default $\phi=0^\circ$ is the E-plane
  cut for the current incident polarization.
\end{description}

For a lighter high-order smoke check, generate the four-elements-per-wavelength
mesh near the sphere and run the same gate with $p=4$ and ESPRK5:
\begin{lstlisting}[language=bash]
gmsh examples/meshes/metallic_sphere_scattering.geo -3 -format vtk \
  -o examples/meshes/metallic_sphere_scattering_epw4.vtk \
  -setnumber ElementsPerWavelength 4 \
  -setnumber SphereMeshSizeFactor 1.0 \
  -setnumber PMLMeshSizeFactor 3.0 \
  -setnumber FarMeshSizeFactor 4.0 \
  -setnumber CurvatureSamples 8 \
  -setnumber PMLWidth 1.0 \
  -setnumber AirBuffer 1.0 \
  -setnumber OptimizeMesh 0

mpiexec -n 2 -genv OPENBLAS_NUM_THREADS 1 julia --project=. \
  examples/validate_coarse_sphere_rcs.jl \
  --mesh=examples/meshes/metallic_sphere_scattering_epw4.vtk \
  --order=4 --esprk-order=5 \
  --final-time=1e-6 --rcs-start-time=1e-6 \
  --rcs-every=1 --diagnostics-every=1 \
  --min-max-rcs=0 \
  --output-dir=output/validation_sequence/coarse_sphere_rcs_epw4_p4_smoke
\end{lstlisting}
The resulting \code{diagnostics/rcs.csv} can be processed with the existing Mie
comparison script:
\begin{lstlisting}[language=bash]
python3 examples/postprocess_metallic_sphere_mie_rcs.py \
  --run-dir output/validation_sequence/coarse_sphere_rcs_epw4_p4_smoke
\end{lstlisting}
The script writes \code{diagnostics/mie\_rcs\_comparison.csv},
\code{tables/mie\_rcs\_comparison.tex}, and
\code{plots/mie\_rcs\_comparison.pdf}. A one-step high-order smoke run
validates the setup, RCS extraction, and postprocessing path; it is not a
quantitative RCS benchmark. For Mie agreement, use a longer final time and
start the Fourier extraction after the transient has left the near field.
The postprocessor figure has two panels: the top panel compares
$10\log_{10}(\sigma/(\pi a^2))$ with the exact Mie curve, while the lower panel
shows $|\sigma_h-\sigma_{\rm Mie}|/|\sigma_{\rm Mie}|$. Large errors in a
one-step or startup-window run indicate that the Fourier estimate is not a
steady monochromatic RCS; they do not by themselves prove that the output
pipeline is wrong. A resolved validation should be stable when
\code{--rcs-start-time}, \code{--rcs-every}, the mesh, and the polynomial order
are varied.

\section{Production Poisson-bracket PML validation}

The production PML validation executable is
\code{examples/distributed\_poisson\_bracket\_pml\_validation.jl}. It uses
the Poisson-bracket Maxwell operator, the H-first ESPRK integrator, periodic
boundary pairs in $y$ and $z$, and nonlinear PML layers at the two $x$
boundaries. By default it reads
\code{examples/meshes/periodic\_box\_structured\_nx4\_ny2\_nz2.vtk}; pass
\code{--mesh} for one mesh or \code{--meshes} for a comma-separated mesh
sweep. Meshes must be axis-aligned cuboids; boundary IDs are inferred
geometrically as $1/2$ on $x_{\min}/x_{\max}$, $3/4$ on
$y_{\min}/y_{\max}$, and $5/6$ on $z_{\min}/z_{\max}$. The loaded mesh is
partitioned with a deterministic balanced spatial partition. The initial
condition is a right-going sine-modulated Gaussian pulse,
\[
  g(x)=
  \exp\left[-\left(\frac{x-x_0}{w}\right)^2\right]
  \sin\left(k_0(x-x_0)\right),
  \qquad
  \vect E=(0,0,\sqrt{\mu/\epsilon}\,g(x)),\qquad
  \vect H=(0,-g(x),0).
\]
By default $\lambda_0=0.5$, so $k_0=4\pi$ and, for
$\epsilon=\mu=1$, $f_0=2$. On
\code{examples/meshes/periodic\_box\_structured\_nx16\_ny8\_nz8.vtk}, this is
four $x$-elements per central wavelength.

\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/distributed_poisson_bracket_pml_validation.jl \
  --mesh=examples/meshes/periodic_box_structured_nx16_ny8_nz8.vtk \
  --order=2 --esprk-order=3 \
  --final-time=3.0 --cfl=0.15 \
  --central-wavelength=0.5 \
  --fluxes=centered,alternating \
  --pml-widths=0.25,0.5 \
  --sigma-maxes=8,12 --sigma-degrees=2,3 \
  --paraview-every=25
\end{lstlisting}

The command above runs a Cartesian product sweep over mesh, flux kind, PML
width, maximum damping, and damping polynomial degree. Each case gets its own
isolated run directory below
\code{output/poisson\_bracket\_pml\_validation}. The root directory also
contains \code{sweep\_summary.csv}, with one row per case and columns for the
mesh path, central frequency, central wavelength, central wavenumber, final
energy ratio, reflection ratio, maximum reflected left-monitor energy, time
step, step count, and case output directory.

The case diagnostics are:
\begin{description}[style=nextline]
  \item[\code{diagnostics/energy.csv}]
  Global electric, magnetic, total, and component Hamiltonian energies.

  \item[\code{diagnostics/reflection\_diagnostics.csv}]
  Quadrature-integrated total energy, left-PML energy, right-PML energy,
  interior energy, left-monitor energy, right-monitor energy, the maximum
  left-monitor energy after the configured reflection start time, and the
  normalized reflection ratio.

  \item[\code{fields.pvd} and \code{fields/}]
  ParaView time-series output using parallel high-order VTK Lagrange
  tetrahedra. The analytical arrays are zero placeholders for this validation
  pulse; the reflection diagnostics are the quantitative validation output.

  \item[\code{config/} and \code{input/}]
  Resolved configuration, input manifest, run metadata, partition metadata,
  and run-layout metadata.
\end{description}

The default reflection start time is estimated from the pulse center, wave
speed $c=1/\sqrt{\epsilon\mu}$, and the right PML interface. Override it with
\code{--reflection-start} when the monitor placement or pulse shape changes.
The left monitor is \code{x <= --left-monitor-max}; the right monitor is
\code{x >= --right-monitor-min}. Alternating Poisson-bracket fluxes currently
support only PEC outer boundaries, so the validation driver rejects
\code{--flux=alternating --outer-boundary=pmc} and
\code{--flux=alternating --outer-boundary=absorbing} before time stepping.

  --output=output/convergence_distributed_poisson_bracket_pmc.csv
\end{lstlisting}
The accepted values are \code{pec} and \code{pmc}, case-insensitively, with
\code{pec} as the default. The output CSV records the selection in its
\code{boundary\_condition} column.

The same driver can generate an unstructured Gmsh mesh family on the unit
cube:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/convergence_distributed_poisson_bracket_maxwell.jl \
  --mesh-family=unstructured \
  --nx-targets=2,4,8,16 \
  --orders=2,3,4 \
  --periods=1 \
  --output=output/convergence_distributed_poisson_bracket_unstructured.csv
\end{lstlisting}
Rank zero invokes Gmsh on
\code{examples/meshes/unit\_cube\_unstructured.geo}, writes VTK meshes under
\code{--mesh-dir}, and then uses the same root-distribution and spatial
partitioning path as the structured study. If \code{--mesh-dir} is omitted,
the directory is named \code{convergence\_unstructured\_meshes} beside the
output CSV directory.
The convenience options are:
\begin{itemize}[leftmargin=*]
  \item \code{--mesh-family=structured|unstructured};
  \item \code{--nx-target=N --levels=L}, which generates
        \(N,2N,4N,\ldots\);
  \item \code{--nx-targets=a,b,c}, which selects an explicit unstructured
        family and overrides the base target and level count;
  \item \code{--geo=PATH}, to select another parameterized Gmsh geometry;
  \item \code{--mesh-dir=PATH}, to preserve generated VTK files in a chosen
        directory.
\end{itemize}
For unstructured runs, the values printed as levels are Gmsh
\code{NxTarget} values. They request \(h_{\mathrm{target}}=L_x/N_x\), but the
rate calculation uses the measured volume-based
\[
  h_{\mathrm{char}}=
  \left(\frac{|\Omega|}{N_{\mathrm{el}}}\right)^{1/3}.
\]
The CSV records \code{mesh\_family} in addition to
\code{boundary\_condition}, so structured and unstructured cavity results are
distinguishable in post-processing. The post-processing script also accepts
older PEC CSV files without these newer columns.

\section{Distributed periodic plane-wave convergence study}

The periodic convergence driver uses the traveling plane wave from the
distributed periodic experiment:
\[
  E=(0,0,-\sin(2\pi x-2\pi t)),\qquad
  H=(0,\sin(2\pi x-2\pi t),0).
\]
Run one complete wave period with:
\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \
  examples/convergence_distributed_periodic_poisson_bracket_maxwell.jl \
  --nx-targets=4,8,16 \
  --orders=2,3,4 \
  --periods=1 \
  --output=output/convergence_distributed_periodic_poisson_bracket.csv
\end{lstlisting}

Rank zero invokes Gmsh on
\code{examples/meshes/periodic\_box\_unstructured.geo}. The default
\code{--nx-target=2 --levels=4} generates
\[
  N_x=2,4,8,16,\qquad
  h_\ell=\frac{L_x}{N_x}
        =h_0\,2^{-\ell},\quad \ell=0,1,2,3.
\]
Equivalently, \code{--nx-targets=4,8,16} selects an explicit family and is a
better starting point for production convergence checks on the current
unstructured geometry. The result is an unstructured periodic tetrahedral
mesh family with uniformly halved requested mesh size. Boundary tags
\(1\leftrightarrow2\), \(3\leftrightarrow4\), and \(5\leftrightarrow6\) are
paired by the production distributed periodic exchange.

The driver records two different mesh-size measures:
\[
  h_{\mathrm{target}}=\frac{L_x}{N_x},
  \qquad
  h_{\mathrm{char}}=
  \left(\frac{|\Omega|}{N_{\mathrm{el}}}\right)^{1/3}.
\]
The first quantity is stored as \code{target\_h} and is the Gmsh request. The
second quantity is stored as \code{characteristic\_h} and is measured from the
generated distributed mesh. Observed rates are computed from
\code{characteristic\_h}:
\[
  p =
  \frac{\log(e_{\mathrm{coarse}}/e_{\mathrm{fine}})}
       {\log(h_{\mathrm{char,coarse}}/h_{\mathrm{char,fine}})}.
\]
This is deliberate. Independently generated unstructured Gmsh meshes are not
nested, and doubling \code{NxTarget} does not guarantee that the realized
tetrahedral volume scale is exactly halved. The console therefore also prints
the ratios of \code{target\_h} and \code{characteristic\_h}. CSV files
generated before this convention should be regenerated before rate
comparisons.

The CSV schema matches the cavity convergence driver and records
\code{periodic} in the \code{boundary\_condition} column. It additionally
records \(L^2\) errors and rates for every component
\(E_x,E_y,E_z,H_x,H_y,H_z\), aggregate electric, magnetic, and total errors,
\code{h\_min}, \code{h\_max}, energy error, charge diagnostics, and sampled
\(L^\infty\) errors. For this analytical wave, the active components are
\(E_z\) and \(H_y\). The exact components
\(E_x,E_y,H_x,H_z\) are zero, so their norms measure transverse
polarization leakage. The console reports the combined leakage measures
\[
  \left(\left\lVert E_x\right\rVert_{L^2}^2+
        \left\lVert E_y\right\rVert_{L^2}^2\right)^{1/2},
  \qquad
  \left(\left\lVert H_x\right\rVert_{L^2}^2+
        \left\lVert H_z\right\rVert_{L^2}^2\right)^{1/2}.
\]

The finest refinement pair is checked against strict aggregate targets:
electric rate \(N+1\) and magnetic rate \(N\), with the same half-order
acceptance tolerance as the cavity study. This is a regression target, not a
generic theorem for every unstructured tetrahedral family. On general
unstructured meshes the exact-zero components can converge closer to order
\(N\); if those leakage components dominate the vector norm, the aggregate
electric rate can fail the strict \(N+1\) target even when the active
\(E_z\) and \(H_y\) plane-wave components converge at the expected rate.
Inspect the component table, leakage table, and mesh-size-ratio table before
interpreting a failed strict verdict.

\section{Serial VTU field output}

The stationary PEC examples contain helper functions that write either:

\begin{itemize}[leftmargin=*]
  \item cell-centered fields for order zero; or
  \item discontinuous vertex fields for order one and above.
\end{itemize}

The discontinuous writer duplicates tetrahedron vertices per element. This is
intentional: a DG solution may have two different traces at the same geometric
vertex.

\section{Partition output}

\api{write_partition_vtk} writes the complete mesh with a partition cell
array. \api{write_partition_piece_vtks} writes one owned-element mesh per
partition. These are mesh visualization utilities; they do not write the
distributed Maxwell solution.

\section{Distributed mesh files}

The first production run may prepare one owned-plus-halo mesh shard per MPI
rank:

\begin{lstlisting}[language=julia]
prepare_distributed_mesh_partition(
    root_mesh,
    root_partition,
    "mesh_cache";
    comm = MPI.COMM_WORLD,
)
\end{lstlisting}

Later runs bypass global mesh loading and root distribution:

\begin{lstlisting}[language=julia]
distributed_dg = build_distributed_dg_from_partition(
    "mesh_cache",

\end{lstlisting}

The directory contains \code{mesh\_manifest.toml} and one checksummed binary

write_distributed_checkpoint(

\section{ParaView time series}

The distributed Poisson-bracket experiment writes owned elements only,
preserves global element IDs and owner ranks, and represents DG discontinuities
with element-local points. Use:

\begin{lstlisting}[language=bash]
mpiexec -n 2 julia --project=. \

\end{lstlisting}

Open \code{fields.pvd} in ParaView. It indexes
\code{fields/fields\_stepNNNNNNNN.pvtu}. The periodic driver writes each

\(N>1\) are not reduced to a four-corner linear visualization. Its rank-local
VTU pieces contain the numerical, exact, and error vectors for \(E\) and
\(H\), their magnitudes, global element IDs, owner rank, polynomial order, and
physical time.

\section{Run I/O organization}

The production Maxwell drivers treat each \code{--output-dir} as one isolated
run directory. A run directory is intended to be a complete scientific record:
it contains the resolved configuration, input provenance, diagnostics,
visualization files, checkpoint data, and status metadata for one execution.
The current canonical layout is:

\begin{lstlisting}[language=bash]
RUN_DIR/
  config/
    run_layout.toml
    resolved_config.toml
    run_metadata.toml
    partition_metadata.csv
  input/
    input_manifest.toml
  diagnostics/
    energy.csv
    quadrature_diagnostics.csv
    integration_points_rankNNNN.csv
  fields/
    fields_stepNNNNNNNN.pvtu
    rank-local VTU pieces
  checkpoints/
    stepNNNNNNNN/
    latest.toml
  logs/
  plots/
  tables/
  fields.pvd
  paraview_series.csv
  status.toml
\end{lstlisting}

The \code{logs/}, \code{plots/}, and \code{tables/} directories are created by
the run-layout layer even when the production driver itself does not write
into them. They provide stable locations for scheduler logs, post-processing
figures, and derived tables.

For compatibility with older plotting and post-processing scripts, the run
root also contains symlinks:
\begin{lstlisting}[language=bash]
RUN_DIR/energy.csv -> diagnostics/energy.csv
RUN_DIR/quadrature_diagnostics.csv -> diagnostics/quadrature_diagnostics.csv
RUN_DIR/run_metadata.toml -> config/run_metadata.toml
RUN_DIR/partition_metadata.csv -> config/partition_metadata.csv
\end{lstlisting}
New tools should prefer the canonical paths in \code{diagnostics/} and
\code{config/}. Older scripts that read the root-level CSV and TOML filenames
continue to work through the symlinks.

\subsection{Automatic isolated run directories}

When \code{--output-dir} is supplied, the driver writes exactly there. For
routine numerical experiments, prefer \code{--run-root}. This creates a
timestamped subdirectory automatically:

\begin{lstlisting}[language=bash]
mpiexec -n 4 julia --project=. \
  examples/distributed_periodic_poisson_bracket_maxwell.jl \
  --run-root=output/runs \
  --run-name=periodic-cuboid-af-p4m1-r4 \
  --partitions=4 \
  --flux=alternating \
  --order=4 --esprk-order=5
\end{lstlisting}

The resulting directory has the form
\begin{lstlisting}[language=bash]
output/runs/20260708T153000_periodic-cuboid-af-p4m1-r4/
\end{lstlisting}
where the timestamp is generated once on rank zero and broadcast to all MPI
ranks. The run name is sanitized to lower-case path-safe text. If
\code{--run-name} is omitted, the driver constructs a name from the problem
class, flux, polynomial order, and MPI rank count.

\code{--run-root} and \code{--output-dir} are intentionally mutually
exclusive. Use \code{--output-dir} when an exact path is required, and use
\code{--run-root} when a study launches many runs and each run should be
isolated automatically.

\subsection{Configuration and input provenance}

\code{config/resolved\_config.toml} stores the fully resolved driver
configuration, including defaults that were not explicitly typed on the CLI.
\code{input/input\_manifest.toml} records the mesh path, partition path,
distributed mesh cache, checkpoint directory, restart checkpoint, and mesh-load
mode used by the run. \code{config/run\_layout.toml} records the resolved
directory paths themselves.

\code{status.toml} is a small machine-readable status file. It is first written
as \code{prepared}, then updated to \code{running}, and finally to
\code{complete}. The final status contains the final step, final time, elapsed
integration time, and final checkpoint path.

\subsection{Checkpoint paths}

By default, checkpoints are written to \code{RUN\_DIR/checkpoints/}. Supplying
\code{--checkpoint-dir=PATH} overrides this and can place checkpoints outside
the run directory. This is useful on machines with a dedicated high-throughput
scratch filesystem, but it reduces the self-contained nature of the run
artifact. When using an external checkpoint directory, keep the
\code{input/input\_manifest.toml} file with the run because it records the
external path.

\section{Run and partition metadata}

Every production experiment writes:

\begin{itemize}[leftmargin=*]
  \item \code{config/run\_metadata.toml}: configuration, Julia version, MPI
        size, time-step data, elapsed solve time, and final checkpoint;
  \item \code{config/partition\_metadata.csv}: owned and ghost elements, local
        nodes, neighbor ranks, interface-face counts, halo-size ratios,
        send/receive buffer sizes, and global element ranges;
  \item \code{config/resolved\_config.toml}: resolved driver configuration;
  \item \code{input/input\_manifest.toml}: mesh, partition, distributed mesh
        cache, checkpoint, restart, and load-mode provenance;
  \item \code{status.toml}: prepared/running/complete status and final run
        summary;
  \item \code{paraview\_series.csv}: step, time, and PVTU dataset index.
\end{itemize}

\chapter{Diagnostics and Troubleshooting}

\section{MPI run hangs}

\begin{itemize}[leftmargin=*]
  \item Confirm every rank enters the same collective constructor and time
        integration sequence.
  \item Confirm the launch rank count matches the partition file.
  \item Confirm MPI.jl and \code{mpiexec} use compatible MPI libraries.
        Inspect the configured backend with
        \code{julia --project=. -e 'using MPI; MPI.versioninfo()'} and use
        \code{mpiexecjl} when the system launcher targets a different MPI
        implementation.
  \item Do not let only rank zero call \code{distributed\_maxwell\_energy};
        it contains an \code{Allreduce}.
  \item Ensure all ranks use the same communication tag for a given exchange.
\end{itemize}

\section{Wrong interface flux or rank-dependent error}

\begin{itemize}[leftmargin=*]
  \item Run \code{test\_mpi\_face\_permutation.jl}.
  \item Check tetrahedron connectivity and face orientation.
  \item Check that face-node generation is identical on all ranks.
  \item Tighten or relax \code{trace\_tol} only after inspecting mesh scale.
  \item Verify that the partition includes complete face adjacency, not merely
        node adjacency.
\end{itemize}

\section{Missing or incorrect boundary conditions}

\begin{itemize}[leftmargin=*]
  \item Confirm the VTU file contains triangular boundary cells.
  \item Confirm their cell-data array is named \code{boundary\_id}, or pass a
        different \code{boundary\_tag\_name}.
  \item Print \code{unique(tri\_data(mesh, "boundary\_id"))}.
  \item Register every physical PEC tag explicitly.
  \item Remember that tag 10 is a convention in the examples, not a hard
        requirement of the solver.
  \item For the periodic box driver, verify tags $1\leftrightarrow2$,
        $3\leftrightarrow4$, and $5\leftrightarrow6$ and matching translated
        triangulations.
  \item Periodic tags belong in the periodic exchange and should map to
        \code{MaxwellBC\_None} in the physical-boundary registry.
\end{itemize}

\section{Periodic driver fails during partitioning}

\begin{itemize}[leftmargin=*]
  \item Confirm \code{mpmetis} is installed and visible in \code{PATH}.
  \item Confirm \code{--partitions} equals the \code{mpiexec -n} rank count.
  \item Use \code{--partitions=N} for the rank count. The singular option
        \code{--partition=PATH} is only for an existing partition file.
  \item If a partition contains a different number of entries than the mesh
        has tetrahedra, regenerate it for that mesh with
        \code{--repartition}.
  \item Use \code{--repartition} after replacing the source mesh.
  \item Use \code{--rebuild-distributed-mesh} after changing the partition.
  \item Use DG order two or higher for the supplied traveling wave.
\end{itemize}

\section{Unstable time integration}

\begin{itemize}[leftmargin=*]
  \item Reduce the CFL factor.
  \item Inspect the worst element reported by
        \code{element\_size\_diagnostics}.
  \item Check for degenerate or highly skewed tetrahedra.
  \item Verify positive $\varepsilon$ and $\mu$.
  \item Use the upwind Hesthaven--Warburton flux when damping unresolved jumps
        is acceptable.
  \item Confirm that the chosen RK or ESPRK order is supported.
\end{itemize}

\section{Poisson-bracket errors}

\begin{itemize}[leftmargin=*]
  \item Use \code{PoissonBracketFormulation()} with central flux only.
  \item Use the partitioned symplectic driver.
  \item Set \code{first\_partition = :H}.
  \item Use ESPRK order one through six.
\end{itemize}

\section{Threaded run is slower}

\begin{itemize}[leftmargin=*]
  \item Increase the problem size; small meshes are overhead dominated.
  \item Verify the actual Julia thread count.
  \item Avoid oversubscribing cores in hybrid MPI/threaded runs.
  \item Pin ranks and threads appropriately for the machine.
  \item Use the benchmark harness and compare median times.
\end{itemize}

\section{Memory use is larger than expected}

\begin{itemize}[leftmargin=*]
  \item Use \code{build\_distributed\_dg\_from\_partition} for repeated runs,
        or \code{build\_distributed\_dg\_from\_root} during preparation.
  \item Remember that each rank stores owned elements plus one face halo.
  \item Higher polynomial order increases storage in proportion to $N_p$.
  \item Explicit RK methods store several complete right-hand sides.
  \item Root temporarily retains the complete global mesh and partition only
        while preparing rank-local mesh files.
\end{itemize}

\chapter{Current Limitations and Roadmap}

\section{Current limitations}

\begin{itemize}[leftmargin=*]
  \item Three-dimensional tetrahedral meshes only.
  \item Affine straight-sided tetrahedral geometry.
  \item Source-free Maxwell equations.
  \item Material coefficients are isotropic and piecewise constant per
        tetrahedron; curved or nodally varying tensors are not implemented.
  \item The characteristic absorbing boundary is first order. It is separate
        from the nonlinear PML and remains useful as an outer termination.
  \item The nonlinear PML supports scalar homogeneous coefficients and
        piecewise-constant isotropic \code{MaxwellElementMaterials}. Anisotropic
        material tensors and nodally varying material coefficients are not
        implemented.
  \item The nonlinear PML is dissipative, so ESPRK runs with PML should be
        interpreted as the selected partitioned update applied to a damped
        right-hand side, not as a conservative symplectic map.
  \item No adaptive mesh refinement.
  \item No distributed mesh repartitioning during a run.
  \item Checkpoint restart requires the same MPI rank count and partition.
  \item Rank-local mesh files currently require a shared filesystem.
  \item Initial mesh-cache preparation still reads and partitions the complete
        mesh on root; subsequent runs are rank-local.
  \item Communication is nonblocking, but currently completed before local DG
        evaluation; volume work is not yet overlapped with trace exchange.
  \item Stored ghost elements currently pass through local volume evaluation
        before ghost residuals are cleared.
\end{itemize}

\section{Recommended next development stages}

\begin{enumerate}[leftmargin=*]
  \item Add impressed electric and magnetic sources.
  \item Add anisotropic and within-element varying material tensors.
  \item Validate nonlinear-PML reflection errors for oblique incidence, material
        jumps, and corner layers.
  \item Add alternative higher-order absorbing boundary conditions.
  \item Split the right-hand side into owned volume work and interface surface
        work, then overlap communication.
  \item Skip ghost volume computation.
  \item Add MPI strong- and weak-scaling benchmarks.
  \item Add repartitioning restart and portable long-term checkpoint formats.
  \item Add direct parallel ingestion from partition-aware mesh formats so
        cache preparation also avoids root assembly.
\end{enumerate}

\chapter{Reproducibility Checklist}

Record the following information with every reported result:

\begin{itemize}[leftmargin=*]
  \item \pkg{} commit hash and working-tree status;
  \item Julia version and project/manifest state;
  \item MPI implementation and version;
  \item number of MPI ranks and Julia threads per rank;
  \item CPU/node allocation and affinity settings;
  \item mesh file, tetrahedron count, boundary tags, and partition file;
  \item polynomial order $N$, $N_p$, and $N_{fp}$;
  \item formulation and flux;
  \item RK or ESPRK order and partition order;
  \item $\varepsilon$, $\mu$, CFL, $\Delta t$, and number of steps;
  \item PML interface locations, $\sigma_{\max}$, profile degree, $a$, and
        denominator regularization when nonlinear PML damping is active;
  \item initial condition and boundary registry;
  \item initial/final energy and error norms;
  \item output and benchmark methodology.
\end{itemize}
